# 0.97.0+26.2 — the 0.97.0 feature set on Minecraft 26.2

Made for **Minecraft 26.2** (Fabric, Java 25). This is the same mod version as the 26.3 release;
the `+26.2` suffix is the build, not a new feature set. The 26.3 build is the `v0.97.0` release.

---

## ⚠️ Read this first — Baritone is REQUIRED, and it is INCLUDED

**There is nothing else to download.** Baritone is the movement engine — pathing, mining and
collecting dropped items — and it **ships inside this jar** as a Fabric nested JAR. UnionClef
declares it under `depends` (`baritone >=1.19.0`), so the requirement is enforced rather than
assumed.

1. Drop **`unionclef-0.97.0+26.2.jar`** into `mods/`.
2. Launch with **Java 25**.

That is the whole install. On first launch the log should show:

```
Baritone bridge ready.
Baritone settings applied: freeLook=false smoothLook=true ...
```

The second line names every tuned value actually set, and flags any this Baritone build refused —
so "the optimal defaults are applied" is something you can check, not assume.

**Already have your own Baritone?** Keep it. Fabric Loader resolves one version per mod id, so a
copy in `mods/` takes priority over the bundled one.

Bundled: `baritone-api-fabric-1.19.0.jar` (LGPL-3.0, unmodified) — the Baritone release built for
26.2. Its licence travels with the jar at `META-INF/licenses/LGPL-3.0.txt`.

## What differs from the 26.3 build

Nothing in behaviour was forked. These are the 26.2 adaptations, all verified by compiling against
the 26.2 client jar:

- **Baritone 1.19.0** is bundled instead of 1.20.0. The bridge's reflection surface was checked
  against both: same settings fields, same process/goal classes, same `IMineProcess` /
  `IFollowProcess` methods.
- **Fuel times come from `Level.fuelValues()`.** 26.3 moved burn times onto a `cooking_fuel` item
  component with a `CONTEXT_INT_PROVIDER` registry; neither exists in 26.2. The 26.2 build asks the
  world's `FuelValues` (the data-map replacement for the old static fuel table), so datapack and
  modded fuels are still correct. With no world loaded yet, it falls back to vanilla burn times.
  `isFuel`, `getFuelAmount` and the smelting chain behave as before.
- **API spellings that changed between 26.2 and 26.3:** `EnderMan` (26.3: `Enderman`),
  `InputConstants.Type.KEYSYM` (26.3: `KEYBOARD`), `InputConstants.isKeyDown(Window, int)`,
  `VanillaRegistries.createLookup()`, `SignBlockEntity#getText(boolean)`,
  `SignText#getMessages(boolean)` returning `Component[]`, and the two-argument
  `LivingEntity#swing(InteractionHand, boolean)` (26.3 added a `SwingAnimation` overload).
- **Metadata:** `minecraft ~26.2`, `cloth-config >=26.2`, `baritone >=1.19.0`.

Everything else — the Baritone-driven movement, humanised aiming, door opening, combat facing,
chain registry, GUI, bridges and shutdown watchdog — is the 0.97.0 work described in the
[26.3 release notes](https://github.com/smallduuude/unionclef-26.3-native/blob/main/docs/releases/0.97.0.md).

## Coverage and known gaps

The item-coverage audit was measured against the 26.3 jar, and this build ships the same chains
over the 26.2 registry. Items that exist only in 26.3 (for example `poplar`) are absent from the
26.2 registry and therefore cannot be reached — that is a registry difference, not a missing
chain. See [`docs/features/ITEM_BLOCK_COVERAGE.md`](https://github.com/smallduuude/unionclef-26.3-native/blob/26.2/docs/features/ITEM_BLOCK_COVERAGE.md) for the
audit and [`TODOS.md`](https://github.com/smallduuude/unionclef-26.3-native/blob/26.2/TODOS.md) for the outstanding work: structure loot, archaeology,
husbandry, maps, buckets, elytra, dragon breath, and older music discs.
