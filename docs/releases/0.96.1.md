# 0.96.1 — mining and water fixes on 26.3

Two runtime bugs reported after the 26.3 port, both intent-vs-behaviour mismatches
that compiled fine.

## `@mineblock` (and every `DestroyBlockTask`) — looked at the block but would not mine

`DestroyBlockTask` only presses the attack key while `LookHelper.isLookingAt(mod, pos)`
is true, and otherwise releases it and re-aims (`dbAimWait`). That gate used tungsten's
own raytrace only (`RotationHelper.isLookingAt`). Where that raytrace disagreed with the
game's real crosshair on 26.3, the miner held attack for **zero** ticks — "looks but
never mines", with the camera appearing to flick between blocks.

`LookHelper.isLookingAt` now **also accepts vanilla's own crosshair**
(`Minecraft.hitResult`) when it names the same block. That is the block a left-click
actually breaks, so agreeing with it can only remove false "not looking" answers.

## In water, the bot stayed afloat looking down (`@hero`, any swim)

`MovementSwim`'s aim computes a full rotation — **pitch included**: level for a
level/rising stroke, down for a dive. But it passed `forceRotations=false`, and
`Movement.updateAimTarget` sends **unforced** targets to
`setTargetFast(yaw, player.getXRot())` — the aimed yaw is applied, the aimed pitch is
thrown away and the current pitch is kept. A body that entered the water looking down
kept looking down, "forward" kept pushing it down while `JUMP` pushed it up, and it
bobbed in place. It passed earlier testing only because the bot happened to enter the
water level.

The swim aim is now **forced** (`MovementTarget(aim, true)`), which routes it through
`WindMouseRotation.setTarget(yaw, pitch)` — still the pixel-quantised mouse pipeline, so
the correction stays humanised and anti-cheat-safe. `BlockPathWalker` (pitch 0),
`SprintPolicy` (explicit current pitch) and `moveTowards` (forces `withPitch(current)`)
already worked this way; the swim stroke was the odd one out.

## Build / test

- `gradlew clean build` green for altoclef + tungsten (Java 25).
- Jar installed to the 26.3 test instance: `unionclef-0.96.1+26.3.jar`.

## How to test

- Mining: `@mineblock` and `@get cobblestone 1`. The block should break; the top-left
  task overlay should read `Block in range, mining...` rather than sitting on the aim
  wait.
- Water: drive the bot into a lake with `@goto`/`@hero` and watch it cross and climb
  out. It should look level (or up) while swimming, not pin the pitch at the water's
  surface.
